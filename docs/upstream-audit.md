# Upstream architecture audit

Reviewed the upstream snapshot identified in [NOTICE](../NOTICE) before implementing the new pipeline.

| Area | Execution path | Bottleneck or limitation |
| --- | --- | --- |
| CLI | The launcher in scripts/run.py selects the bundled or explicit environment, prepends src, and calls the argparse dispatcher in cli.py. The CLI owns the output lock and translates flags to Config. | The dispatcher handles both evidence collection and account/publishing commands. The original audit required separate commands and analyst handoffs. |
| Frontier | engine.py initializes SQLite in WAL mode. The urls table stores URL, depth, source, state and reason. The meta table stores run configuration, sitemap metadata and run state. The pages and sitemap_urls tables retain page payloads and membership. Resume resets interrupted fetching states to pending after validating config. | The query-variant cap scans queued URLs for a path, and the persistent queue orders candidates in batches. Snapshot resume recovers pending work but does not refresh a prior crawl incrementally. |
| Fetch and render | network.py normalizes URLs, enforces scope and destination policy, spaces requests, and interprets robots. engine.py fetches batches using HTTP workers, commits results in queue order, and enqueues links. render.py optionally launches Chromium with checked request routing. | Browser rendering happens sequentially in isolated contexts. Auto rendering uses heuristics, and an HTTP response with a script shell can need an explicit browser check. |
| Findings | extract.py uses BeautifulSoup for metadata, links, structured data and text. evidence.py resolves raw versus rendered evidence and suppresses absence claims for partial captures. review.py computes readiness and performs site-wide entity review. findings.py attaches evidence and acceptance criteria. | Much of AEO and GEO methodology lived in playbooks. Type inventories and entity identities lacked a dedicated nested-property and reference validator. Canonical checks depended on captured targets. |
| Search and discovery | discovery.py offers budgeted native adapters and imports host-search and browser evidence with provenance. research.py builds profiles, buyer queries and competitor comparisons. | The host had to review profile and query quality and collect the competitor cohort. Providers can limit access, and a search lead alone cannot establish a backlink. |
| Backlinks | backlinks.py verifies source pages and late rendered links. reputation.py scores the sample and coverage. The catalog retains 206 deduplicated site entries from 241 source rows. | The catalog contains unreviewed entries and unverified sheet DR. Catalog and search coverage cannot establish authority across the whole web. |
| Specialist workflow | SKILL.md, docs and playbooks define technical SEO, AEO, GEO, content, entity and reputation specialties. research_cli.py creates assignments and installs host definitions. | The assignment generator did not execute specialist work. Publishing requires explicit review and a permitted host browser. |
| Reporting and changes | reports.py renders reviewed HTML and PDF evidence. onsite.py and publishing.py stage verified single-file plans with hash checks. | Automation had no unified health gate, scheduled target workflow or Git-native proposal for reviewed framework metadata. |

The new [health pipeline](../README.md#architecture) composes these existing evidence paths. It adds bounded checks, reads the same saved snapshots and keeps independent proof and publication outside the crawler.
